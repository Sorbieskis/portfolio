System: "Docs-as-Code" Technical Documentation Workflow

Systems Engineer | Deimonas Suchanka

Foundation for Automated Documentation

Independently architected a modern documentation system from the ground up, replacing a chaotic file-based process with a version-controlled, single-source-of-truth workflow.

the problem

The existing process for creating technical manuals was non-existent. It consisted of scattered Word documents on a shared drive with no version control, inconsistent formatting, and outdated or incomplete information. This led to customer complaints and created significant internal inefficiency.

methodology

  1. 1. Research & Prototyping

    Initially researched and attempted to implement a complex pipeline to integrate with legacy `.docx` workflows, but found it to be unmanageable.

  2. 2. Strategic Pivot

    Pivoted to a more robust and pragmatic "docs-as-code" approach, leveraging proven tools to build a new system from first principles.

  3. 3. System Development

    Established a complete development environment using VSCode, created a comprehensive style guide, and built out reusable templates through iterative experimentation.

  4. 4. Implementation & Delivery

    Authored new, high-quality technical manuals using the system, including taking ownership of custom technical illustrations by editing P&ID schematics in progeCAD.

solution architecture

  • Version Control as Foundation

    Used Git for rigorous version control, providing a complete history of changes and establishing a single source of truth for all documentation.

  • Dual-Output Workflow

    Architected two parallel pipelines: a LaTeX-based workflow for superior typesetting in physical, print-ready manuals, and a Markdown-based workflow for responsive, searchable static websites (using MkDocs).

  • Forward-Thinking Distribution

    Developed a self-contained `.exe` of the software manual using Tauri 2.0 as an interim solution for clients, with a long-term plan to integrate the documentation directly into the control software (CRS10).

  • Foundation for Automation

    Designed the entire system with a "Lego block" philosophy, creating a modular foundation that will enable the future automatic generation of machine-specific manuals based on a given configuration.

deliverables

Documentation Workflow A complete, version-controlled system for generating both print (LaTeX) and web (Markdown/MkDocs) documentation from a structured process.
Style Guide & Templates A comprehensive style guide and a set of boilerplate templates to ensure all future documentation is consistent, professional, and high-quality.
Software Manual Prototype A fully functional static website and a self-contained `.exe` (via Tauri 2.0) for the CRS10 software manual, approved by the lead developer and automation lead.

*Note: The system architecture and templates are proprietary and are available to be discussed in detail during an interview.
